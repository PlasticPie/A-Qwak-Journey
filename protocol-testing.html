Keeping both ends in agreementGarder les deux bouts d'accord

A protocol version gate, byte-exact round-trip tests, golden bytes, shared codecs, and codes instead of words.Une porte de version, des tests aller-retour à l'octet près, des octets d'or, des codecs partagés, et des codes plutôt que des mots.

The most expensive bug in the project

Every wire format in MoonQwak is written twice: once in Build(), once in ParsePayload(). Nothing forces them to agree. Add a field to the writer and forget the reader, or read two fields in the opposite order, and every field after that point decodes as garbage. There is no schema to catch it and no field name to notice. The symptom appears somewhere else: a hull with absurd health, a stream exception three packets later, a feature that "randomly" stops working.

This was, by a wide margin, the costliest class of bug in the project, and it gets more expensive with each packet you add. The answer is three independent layers: a version check that keeps mismatched programs apart, tests that prove each packet round-trips, and shared code so that the most complex formats exist only once.

Le bug le plus cher du projet

Chaque format de fil de MoonQwak est écrit deux fois : une fois dans Build(), une fois dans ParsePayload(). Rien ne les force à être d'accord. Ajoutez un champ à l'écrivain en oubliant le lecteur, ou lisez deux champs dans l'ordre inverse, et chaque champ suivant se décode en bruit. Aucun schéma pour l'attraper, aucun nom de champ pour s'en apercevoir. Le symptôme apparaît ailleurs : une coque à la santé absurde, une exception de flux trois paquets plus loin, une fonctionnalité qui cesse « au hasard » de marcher.

C'était, de loin, la catégorie de bug la plus coûteuse du projet, et elle coûte plus cher à chaque paquet ajouté. La réponse tient en trois couches indépendantes : une vérification de version qui tient à l'écart les programmes désaccordés, des tests qui prouvent que chaque paquet fait l'aller-retour, et du code partagé pour que les formats les plus complexes n'existent qu'une fois.

A version gate at the door

The shared library defines one integer, the protocol version, compiled into every program. The client sends it inside its login packet; the gateway compares it with its own and refuses any difference, in either direction.

Une porte de version à l'entrée

La bibliothèque partagée définit un entier, la version du protocole, compilée dans chaque programme. Le client l'envoie dans son paquet de login ; la gateway la compare à la sienne et refuse toute différence, dans un sens comme dans l'autre.

Gateway/Services/AuthHandlers.cs
public bool HandleLogin(int peerId, Login packet, Server server)
{
    // BEFORE the database, BEFORE the password hash: an outdated client retrying in a
    // loop must not cost a 100,000-iteration PBKDF2 per attempt.
    if (packet.Protocol != ProtocolVersion.Current)
    {
        var clientBehind = packet.Protocol < ProtocolVersion.Current;
        // Two codes, because the culprit differs and the player can only fix the first one.
        server.Send(peerId, new LoginResult(clientBehind ? Code.ClientOutdated : Code.ServerOutdated, ""));
        return true;
    }
    // ... verify credentials, create the session
}

A few details decide whether such a gate helps or annoys:

  • It is checked before anything expensive. The version comparison costs nothing; the password hash is designed to be slow.
  • Strict equality, both ways. Without schema versioning, a newer client is as dangerous as an older one. But the two refusals carry different codes: telling a player "update your client" when the server is the one behind would send them in circles.
  • Old clients are refused with a reason. A client built before the field existed does not send it; the gateway reads 0, which matches no valid version, so the player sees a proper refusal instead of a login screen that never answers.
  • The number changes with every wire change, and only then. The mechanical rule: if the wire tests had to change, the protocol version changes too. Forgetting lets a client in that should have been refused; bumping it for nothing locks everybody out and is noticed in ten seconds. Neither mistake stays silent for long.

The launcher knows the protocol of the build it installs, so when the gateway refuses a client, the message can say which build speaks which protocol instead of just "connection refused" (chapter 8.2).

Quelques détails décident si une telle porte aide ou agace :

  • Elle est vérifiée avant tout ce qui coûte. La comparaison de version ne coûte rien ; le hachage du mot de passe est conçu pour être lent.
  • Égalité stricte, dans les deux sens. Sans versionnage de schéma, un client plus récent est aussi dangereux qu'un plus ancien. Mais les deux refus portent des codes différents : dire « mettez votre client à jour » à un joueur dont le serveur est en retard l'enverrait tourner en rond.
  • Les vieux clients sont refusés avec une raison. Un client compilé avant l'existence du champ ne l'envoie pas ; la gateway lit 0, qui ne correspond à aucune version valide, et le joueur voit un vrai refus au lieu d'un écran de login qui ne répond jamais.
  • Le numéro change à chaque changement de fil, et seulement alors. La règle mécanique : si les tests de fil ont dû changer, la version du protocole change aussi. L'oublier laisse entrer un client qui aurait dû être refusé ; l'incrémenter pour rien bloque tout le monde et se voit en dix secondes. Aucune des deux erreurs ne reste silencieuse longtemps.

Le launcher connaît le protocole du build qu'il installe : quand la gateway refuse un client, le message peut dire quel build parle quel protocole au lieu d'un simple « connexion refusée » (chapitre 8.2).

Rule

Bump the protocol version on every wire change, and on nothing else.

The gate does not remove the risk of mismatched formats; it bounds it to "refused at login, with a reason", which is the cheapest place for it to show up.

Règle

Incrémenter la version du protocole à chaque changement de fil, et à rien d'autre.

La porte ne supprime pas le risque de formats désaccordés ; elle le borne à « refusé au login, avec une raison », l'endroit le moins cher où il puisse se montrer.

Round-trip tests for every packet

The test project, WireTest, holds one filled-in sample of each of the roughly 150 packet types and runs four checks against all of them.

TestWhat it catches
Byte-identical round tripSerialize, parse, serialize again, and require identical bytes. Catches a field written but not read, or read in another order.
Fields surviveCompare every property of the sent and received objects by reflection. Catches a read of the right size into the wrong property, which leaves the bytes perfect.
Truncated framesFeed every prefix of a valid frame to the parser and require a clean refusal. Catches a length check that no longer holds.
CoverageFail the suite if any packet type has no sample, with the type's name in the message. Also fails if two types share an id.

The byte-identical check is the one that carries the suite. It knows nothing about what the fields mean, so a lazy sample cannot fool it: any field that is written and not read breaks it. The reflection check complements it, because swapping two integers of the same width between writing and reading leaves the bytes identical and only the values show the mistake.

Des tests aller-retour pour chaque paquet

Le projet de test, WireTest, contient un échantillon rempli de chacun des quelque 150 types de paquets et exécute quatre vérifications sur tous.

TestCe qu'il attrape
Aller-retour à l'octet prèsSérialiser, parser, resérialiser, et exiger des octets identiques. Attrape un champ écrit mais pas lu, ou lu dans un autre ordre.
Les champs surviventComparer par réflexion chaque propriété des objets envoyé et reçu. Attrape une lecture de la bonne taille dans la mauvaise propriété, qui laisse les octets parfaits.
Trames tronquéesDonner au parseur chaque préfixe d'une trame valide et exiger un refus propre. Attrape une vérification de longueur qui ne tient plus.
CouvertureFaire échouer la suite si un type de paquet n'a pas d'échantillon, avec le nom du type dans le message. Échoue aussi si deux types partagent un identifiant.

L'aller-retour à l'octet près est celui qui porte la suite. Il ne sait rien du sens des champs : un échantillon paresseux ne peut pas le tromper, et tout champ écrit mais non lu le casse. La vérification par réflexion le complète, parce qu'intervertir deux entiers de même largeur entre l'écriture et la lecture laisse les octets identiques ; seules les valeurs trahissent l'erreur.

WireTest/RoundTripTests.cs · one case per packet type
// One [Theory] case per packet type rather than one giant [Fact]: a failure names the
// packet in the test explorer instead of making you read a stack trace.
[Theory]
[MemberData(nameof(PacketSamples.Names), MemberType = typeof(PacketSamples))]
public void RoundTripIsByteIdentical(string name)
{
    var c = PacketSamples.Get(name);
    // serialize → parse → serialize, then compare; the message names the first differing byte
    WireRoundTrip.AssertIdempotent(c.Factory());
}

[Theory]
[MemberData(nameof(PacketSamples.Names), MemberType = typeof(PacketSamples))]
public void FieldsSurviveTheRoundTrip(string name)
{
    var c = PacketSamples.Get(name);
    var sent = c.Factory();
    var received = RoundTripDynamic(sent);
    // every public field and property, by reflection; fields Build() deliberately skips are declared
    WireRoundTrip.AssertFieldsMatch(sent, received, c.Ignored, c.Tolerance);
}

Two decisions make the suite age well. The field comparison uses reflection instead of one assertion per field: a test that has to be extended by hand has exactly the weakness of the code it watches. And the coverage test fails when a new packet has no sample, so silencing it requires a deliberate edit, which is to say a review. Samples must use non-default values everywhere: a field left at zero round-trips perfectly even when nobody writes or reads it, and the test would report success on a field it never checked.

Rule

A test that someone must remember to extend has the same weakness as the code it protects. Make the missing case fail by itself.

Deux décisions font bien vieillir la suite. La comparaison des champs passe par la réflexion plutôt que par une assertion par champ : un test qu'il faut penser à étendre a exactement la faiblesse du code qu'il surveille. Et le test de couverture échoue quand un nouveau paquet n'a pas d'échantillon : le faire taire demande une modification délibérée, donc une relecture. Les échantillons doivent utiliser partout des valeurs non nulles : un champ laissé à zéro fait un aller-retour parfait même quand personne ne l'écrit ni ne le lit, et le test annoncerait un succès sur un champ qu'il n'a jamais vérifié.

Règle

Un test qu'il faut penser à étendre a la même faiblesse que le code qu'il protège. Faire échouer le cas manquant de lui-même.

Golden bytes for shared codecs

A round trip proves that a format agrees with itself. It does not prove that it has not changed: a codec that starts writing velocity before position, and reads it in the same new order, passes every round trip and breaks every client already installed. For the shared codecs of the hottest blocks (chapter 1.2), the tests therefore compare the output with a fixed hexadecimal string, computed by hand with an independent reference encoder.

Des octets d'or pour les codecs partagés

Un aller-retour prouve qu'un format est cohérent avec lui-même. Il ne prouve pas qu'il n'a pas changé : un codec qui se met à écrire la vitesse avant la position, et la lit dans ce même nouvel ordre, passe tous les allers-retours et casse chaque client déjà installé. Pour les codecs partagés des blocs les plus chauds (chapitre 1.2), les tests comparent donc la sortie à une chaîne hexadécimale fixe, calculée à la main avec un encodeur de référence indépendant.

WireTest/WireCodecTests.cs
[Fact]
public void MovementGolden()
{
    MovementFields f;
    f.X = 12.5; f.Y = -3.25; f.Rotation = Math.PI / 2;
    f.VelX = 1.5; f.VelY = -0.75; f.AngularVelocity = 0.25;

    // 12.5×40 = 500 → zig-zag 1000 → 83E8 · −3.25×40 = −130 → 259 → 8103
    // π/2 = a quarter turn = 16384 → 0040 (ushort, little-endian)
    // 1.5×100 → 300 → 812C · −0.75×100 → 149 → 8095 · 0.25×1000 → 500 → 81F4
    var bytes = ProbePacket.Payload(p => MovementWire.Write(p, in f));
    Assert.Equal("83E881030040812C809581F4", ProbePacket.Hex(bytes));
}

Changing a scale is still allowed. It simply fails this test on purpose, which is the reminder that the client libraries must be rebuilt and shipped in the same commit. The sample values also avoid exact half steps, because .NET rounds halves to the nearest even number and a test depending on that convention would be testing the convention.

Changer une échelle reste permis. Ça fait simplement échouer ce test exprès, ce qui rappelle que les bibliothèques du client doivent être recompilées et livrées dans le même commit. Les valeurs d'échantillon évitent aussi les demi-pas exacts, parce que .NET arrondit les moitiés au pair le plus proche et qu'un test qui dépendrait de cette convention testerait la convention.

What the tests cannot see

Snapshots and object details carry bodies written by the server's domain classes and read by the Unity client's classes. The packet library, where the tests live, can reference neither. Those two packets are tested at the layer the library owns (the envelope), with fake objects whose payload imitates the real shape: a flag byte, then a block present only if a bit is set. That covers cursor movement, not agreement on content.

A round trip on the server alone would not close the gap either: it would prove that the server agrees with itself. The gap is closed piece by piece, by moving each hot block into a shared codec, which is both tested with golden bytes and compiled into the client. What remains outside the codecs is the list of flags and counts that decide which blocks are present.

Ce que les tests ne voient pas

Les snapshots et les détails d'objets portent des corps écrits par les classes de domaine du serveur et lus par les classes du client Unity. La bibliothèque de paquets, où vivent les tests, ne peut référencer ni les unes ni les autres. Ces deux paquets sont testés à la couche que possède la bibliothèque (l'enveloppe), avec de faux objets dont la charge utile imite la vraie forme : un octet de drapeaux, puis un bloc présent seulement si un bit est levé. Ça couvre le déplacement du curseur, pas l'accord sur le contenu.

Un aller-retour côté serveur seul ne fermerait pas l'écart non plus : il prouverait que le serveur est d'accord avec lui-même. L'écart se ferme morceau par morceau, en déplaçant chaque bloc chaud dans un codec partagé, à la fois testé en octets d'or et compilé dans le client. Ce qui reste hors des codecs, c'est la liste des drapeaux et des comptes qui décident quels blocs sont présents.

The wire speaks no language

The last kind of disagreement between the two ends is not about bytes but about meaning. For a while, several messages carried French words: a refusal said "Refusé", a map state change said "Guerre civile" (civil war).

Pitfall I hit

To keep a badge up to date, the client compared the received phrase with the label of each value of an enum until one matched. It worked. Translating the game would have switched the badge off silently, without breaking anything visible. A second symptom should have raised the alarm earlier: /selfdestruct had to be added next to /autodestruction, because a French verb is awkward to type for someone else.

The rule that came out of it is the only definitive rule about the wire in the project. A message carries what happened (a code), why (a Detail byte, which is a value of a shared enum: a refusal reason, an attitude, a map state), and data (a player name, a guild name: text typed by a human, untranslatable by nature). It never carries how to say it. Commands are parsed on the client and travel as operation codes; the words live only in the client.

The test is easy to apply to any new field: would translating the game require touching the server? If a string field contains anything other than text a player typed, it is an enum that doesn't know it yet.

Le fil ne parle aucune langue

Le dernier type de désaccord entre les deux bouts ne porte pas sur les octets mais sur le sens. Pendant un temps, plusieurs messages transportaient des mots français : un refus disait « Refusé », un changement d'état de carte disait « Guerre civile ».

Piège rencontré

Pour tenir un badge à jour, le client comparait la phrase reçue au libellé de chaque valeur d'une énumération jusqu'à en trouver une qui corresponde. Ça marchait. Traduire le jeu aurait éteint le badge en silence, sans rien casser de visible. Un second symptôme aurait dû alerter plus tôt : il avait fallu ajouter /selfdestruct à côté de /autodestruction, parce qu'un verbe français est peu pratique à taper pour quelqu'un d'autre.

La règle qui en est sortie est la seule règle définitive du projet sur le fil. Un message porte ce qui s'est passé (un code), pourquoi (un octet Detail, valeur d'une énumération partagée : une raison de refus, une attitude, un état de carte), et des données (un pseudo, un nom de guilde : du texte tapé par un humain, intraduisible par nature). Il ne porte jamais comment le dire. Les commandes sont parsées côté client et voyagent en codes d'opération ; les mots ne vivent que dans le client.

Le test s'applique facilement à tout nouveau champ : est-ce que traduire le jeu obligerait à toucher au serveur ? Si un champ string contient autre chose que du texte tapé par un joueur, c'est une énumération qui s'ignore.

Rule

A packet says what happened, why, and with which data. It never says how to phrase it.

Wording belongs to the client. A server that sends sentences has frozen the game in one language and invited the client to parse them back.

Règle

Un paquet dit ce qui s'est passé, pourquoi, et avec quelles données. Il ne dit jamais comment le formuler.

La formulation appartient au client. Un serveur qui envoie des phrases a figé le jeu dans une langue et invité le client à les reparser.

Key takeaways

  • Hand-written formats disagree silently; plan three layers of defence: a version gate, round-trip tests, shared codecs.
  • Check the protocol version before any expensive work, with distinct refusals for an old client and an old server.
  • Byte-identical round trips catch unread fields; reflection catches swapped fields; coverage tests catch forgotten packets.
  • Freeze shared codecs with golden bytes so that a format change is always a deliberate, visible decision.
  • Keep human language off the wire: codes, reason enums and player-typed data only.

À retenir

  • Les formats écrits à la main divergent en silence ; prévoir trois couches de défense : porte de version, tests aller-retour, codecs partagés.
  • Vérifier la version du protocole avant tout travail coûteux, avec des refus distincts pour un vieux client et un vieux serveur.
  • L'aller-retour à l'octet près attrape les champs non lus ; la réflexion attrape les champs intervertis ; la couverture attrape les paquets oubliés.
  • Figer les codecs partagés en octets d'or, pour qu'un changement de format soit toujours une décision délibérée et visible.
  • Garder la langue humaine hors du fil : des codes, des énumérations de raisons et des données tapées par les joueurs.
