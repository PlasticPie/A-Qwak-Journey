# MoonQwak — MMO architecture field notes

A static, bilingual (English / French) website that documents the technical architecture of the
MoonQwak MMO project: networking, the authoritative simulation, replication, the client,
persistence, the server fleet, updates and the launcher, the world simulation, and the tools used
to measure and harden all of it.

It is written as field notes, not as a prescription: each chapter explains a building block from
first principles, then what this project did, what broke, what was measured and what was decided.
MoonQwak is an ongoing solo project by a developer self-taught in MMO architecture; the site is
shared for educational purposes and will change as the project does.

## Viewing it

There is no build step. Open `index.html` in a browser, straight from the disk (`file://` works),
or serve the folder with any static server:

```sh
npx serve .            # or: python -m http.server 8000
```

Everything is plain HTML, CSS and JavaScript. The only external resource is Google Fonts, with
system fallbacks when it is unavailable.

## Structure

```
index.html              home: hero, the route through all parts, reference cards
start-here.html         0.1, then one HTML file per chapter (see the registry for the order)
topics.html             every chapter, filtered by topic and level
glossary.html           terms, rendered from assets/js/glossary-data.js
lessons.html            every "Rule" callout of every chapter, rendered from the search index
takeaways.html          every chapter's "Key takeaways" list, in reading order, from the same index
TEMPLATE.html           the skeleton and conventions for a new chapter

assets/css/site.css     design tokens (light and dark), layout, components
assets/js/site-data.js  THE registry: parts, chapters (order, level, topics, summaries), topics
assets/js/app.js        page chrome: header, sidebar, rail, search, language and theme, pager
assets/js/widgets.js    interactive figures: charts, steppers, byte strips, animated flows, labs
assets/js/glossary-data.js  the glossary
assets/js/search-index.js   GENERATED by tools/build-index.mjs — do not edit by hand
tools/build-index.mjs   builds the search index and the rules list (Node, no dependencies)
```

## Adding or editing a chapter

1. Add the chapter to `assets/js/site-data.js`: its id, level, topics, architecture nodes,
   prerequisites, and its title and one-line summary in both languages. Add its id to the right
   part's `chapters` list; the list order is the reading order and gives the chapter number.
2. Copy `TEMPLATE.html` to `<id>.html` and set `<body data-page="<id>">`. The template documents
   every convention: bilingual blocks, callout types, code excerpts, figures, charts and widgets.
3. Rebuild the search index:

   ```sh
   node tools/build-index.mjs
   ```

   It prints the number of records, rules, takeaways and glossary terms, and warns about chapters
   listed in the registry whose file does not exist yet. Re-run it after any content change:
   search, the Rules of thumb page, the Key takeaways page and glossary search all read the
   generated file.

## Conventions

- **Two languages, same content.** Each block of text exists as `<div lang="en">` and
  `<div lang="fr">` (or `<span lang>` / `<tspan lang>` inline). CSS shows only the active
  language; the choice is remembered per browser.
- **Callouts** have fixed meanings: Beginner note, Pitfall I hit, Measured, Trade-off,
  In MoonQwak, Rule. Rules are one sentence and are collected on the Rules of thumb page.
- **Code excerpts** are simplified from the project's C# and translated to English. They must stay
  true to the real code's behaviour; keep lines under about 85 characters.
- **Facts come from the code.** The project's design documents drift; when writing or updating a
  chapter, check claims and numbers against the source.
- **Figures** are inline SVG using the `dg-*` classes and theme tokens, so they work in both
  themes. Charts use the `data-chart` JSON block (see the template).
- **Glossary links**: `<a class="term" data-term="id">word</a>` in a chapter; the id must exist in
  `glossary-data.js`.

## Personal links

Fill in `site.links` at the top of `assets/js/site-data.js` (GitHub, LinkedIn, a contact) to show
them in the footer. They are empty by default.

## Deploying

Any static host works, since there is no server-side code:

- **GitHub Pages**: push the folder to a repository, then Settings → Pages → deploy from the
  branch root.
- **Netlify / Cloudflare Pages**: point the project at the folder; no build command, publish
  directory `.`.

Remember to run `node tools/build-index.mjs` before publishing, so the deployed search index
matches the pages.
